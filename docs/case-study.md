# 案例说明：frame-agent

> 本文件对应报名表 D 部分「真实案例证明」。
> 按题目要求的结构填写：任务目标 / 本人职责 / 工具与流程 / 结果与可验证证据。

**仓库地址：** https://github.com/Pine-soot/frame-agent
**代码规模：** 约 30 个源文件，89 个单元测试
**运行要求：** Python ≥ 3.10，零第三方依赖，无需 API Key

---

## 一、任务目标

内容生产团队在批量做短视频时，真正的瓶颈不是"写不出文案"，而是三件事：

1. **质量不可复现** —— 同一套提示词，今天的产出能用、明天不能用，且说不清为什么；
2. **批量生产时质量漂移** —— 为了让美妆类目的钩子更强而改提示词，
   SaaS 类目的脚本被改得不像人话，而且没人发现；
3. **成本不可控** —— 让模型自己"再改改"，可能无限循环烧 token。

所以目标是搭一条流水线，使得：

- 每一次评分都能追溯到具体指标（可复现、可解释）；
- 改完提示词能一键回归，退化立刻暴露（可对比）；
- 成本有硬上限，超支即停并如实降级（可控）；
- 换模型不需要改任何业务代码（可替换）。

## 三、工具与流程

### 3.1 技术栈

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Python 3.10+ | 全项目**零运行期第三方依赖** |
| 模型接入 | 标准库 `urllib` 直连 OpenAI 兼容端点 | 兼容 OpenAI / DeepSeek / 通义 / vLLM / Ollama，不锁定厂商 |
| 离线后端 | 自研确定性 Mock 后端 | 让全链路无需 API Key 可跑通并可复现 |
| 媒体处理 | ffmpeg / ffprobe（可选） | 未安装时自动降级到旁挂清单或合成占位，且如实标注 |
| 测试 | 标准库 `unittest` | 89 个用例，保证"零依赖"承诺在被验证时依然成立 |

### 3.2 流水线流程

```text
brief + 素材
   │
   ▼
Analyst ── 调工具取证（字幕时间轴 / 关键帧清单）
   │       → 场景切分、情绪、屏幕文字、合规风险
   ▼
Scripter ── 生成 N 个不同角度的脚本变体（含分镜表）
   │
   ▼
确定性评测器 ── 五维加权打分，挑最优
   │
   ▼
Critic ── 独立调合规扫描工具复核 → 语义诊断 + 逐条重写指令
   │
   ├─ pass ──▶ 停止
   └─ revise ─▶ 回到 Scripter（带上上一版 + 指令）重新生成
   │
   ▼
PromptOps ── 单变量提示词变体 + 排序
   │
   ▼
报告 + 9 份结构化产物 + 检查点 + 轨迹
```

### 3.3 关键工程手法

- **可保证的结构化输出**：`生成 → 四层宽容 JSON 提取 → Schema 校验 →
  把带 JSONPath 的错误路径回灌修复`，默认 2 轮上限。
- **预算熔断**：调用次数 / token / 墙钟时间三重上限，检查放在调用之前。
- **降级链**：`--backend openai,mock` 时真实模型限流会**自动降级**到离线后端，
  保证生产线永远能出可用产物。
- **不静默降级**：所有降级原因一路带进报告的"降级与风险说明"章节。

### 4.3 与"普通提示词"的能力差异

| 能力 | 一次性提示词 | frame-agent |
| --- | --- | --- |
| 输出结构 | 靠模型自觉，常缺字段 | Schema 校验 + 带路径错误回灌修复 |
| 质量判断 | 模型自评（偏向自己） | 确定性评测器，可复现、可追溯到指标 |
| 迭代改进 | 人手动重问 | 反思循环，达标即停，指令可审计 |
| 成本 | 无上限 | 三重预算熔断，超支即停并标注 |
| 回归验证 | 只能靠人肉看 | 批量套件 + 逐维度均分，退化可见 |
| 换模型 | 重写提示词与解析 | 只改环境变量，业务代码零改动 |

## 五、诚实的边界

这一点必须写清楚，避免被误读：

1. **离线后端的产出是模板化内容，不代表真实创作水平。**
   它的作用是"让流水线可复现地跑通 + 让 CI 覆盖控制流"。
   所有报告都会显式标注 `backend=mock`。真实创作质量必须接入真实模型后重跑同一套评测。
2. **评测器只覆盖可量化的部分。** 钩子的字面强度（数字、长度、悬念标记）能算，
   "这句话是否真有洞察"不能算 —— 那部分交给 Critic，并最终仍需人工终审。
3. **合规词表是内置静态表**，生产环境应替换为平台/法务维护的规则源。
4. **未实现并发调度**，当前为单 brief 串行。

这条边界的写法本身也是刻意的：一个把"能验证的"和"不能验证的"分开标注的系统，
比一个把所有产出都包装成"高质量"的系统更值得信任。

## 六、如果继续做下去

按优先级：

1. **接入真实模型重跑同一套评测**，量化"离线基线 vs 在线效果"的差距（这是受控实验，改动量为零）。
2. **把评测维度与平台真实数据打通**（完播率、CTR），用真实表现反标定 `rubric` 权重 ——
   这是把"主观规则分"变成"预测性分数"的关键一步。
3. **并发调度 + 批量产物看板**，支撑每天数百条的产能。
4. **把合规词表改为可插拔的外部规则源**，并加入人工审核过的误报反馈闭环。
